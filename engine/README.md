# engine/ — 지식이 아닌 것

위키를 **다루는** 도구의 자리입니다. 위키 **내용**은 여기 두지 않습니다 — 그건 `../wiki-vault/` 입니다.

## 왜 나눴나

`wiki-vault/` 가 옵시디언 vault 루트입니다. 그래서 `engine/` 에 있는 것은 검색·그래프·
`[[링크]]` 자동완성에 **구조적으로** 안 섞입니다. 옵시디언 설정으로 숨기는 방법도 있지만,
설정은 기기마다 다시 해야 하고 조용히 풀립니다 — 경계는 레포에 박혀 있어 안 풀립니다.

내용을 적고 싶어지면 여기가 아니라 `wiki-vault/` 로 갑니다. 헷갈리면 기준은 하나 —
**"나중에 이걸 지식으로 검색하고 싶은가?"** 그렇다면 vault 입니다.

## 스크립트

대상 vault 경로는 모두 `WIKI_ROOT` 환경변수를 봅니다. 기본값은 이 레포의 `wiki-vault/` 라
보통은 건드릴 일이 없습니다.

### `init.py` — 첫 실행

`.env` 생성 → 버킷 생성 + versioning → **양성 대조**(넣고 되읽어 바이트 비교) →
**음성 대조**(없는 키가 404 를 내는지).

음성 대조를 같이 하는 이유: 되읽기만 성공하면 "권한이 있다"까지만 알 뿐,
**조회가 아무 키에나 200 을 주는 고장**을 못 가립니다. 그 상태에서는 "이미 있음"(멱등 skip)이
전부 거짓이 됩니다.

### `wiki_lint.py` — 기계적 검사

```bash
python3 engine/scripts/wiki_lint.py            # 사람이 읽는 리포트
python3 engine/scripts/wiki_lint.py --json     # 에이전트용
python3 engine/scripts/wiki_lint.py --quiet    # 문제 있을 때만 (cron 용)
```

**기계가 확실히 아는 것만 잡습니다** — 깨진 `[[링크]]`, 유입 링크 없는 고아, frontmatter 누락,
`raw/` 수정(append-only 위반), `index.md` 누락. 종료코드 = 발견 건수(0 = 깨끗).

판단이 필요한 것(모순·낡은 주장·누락 상호참조·데이터 공백)은 **잡지 않고 목록만 넘깁니다.**
규칙으로 흉내내면 오탐이 나고, **오탐 한 번이면 리포트 전체를 안 보게 됩니다.**
그 넷은 `/gardener --lint` 가 읽고 판정합니다.

### `build_index.py` — `index.md` 생성

```bash
python3 engine/scripts/build_index.py          # 마커 사이를 갱신
python3 engine/scripts/build_index.py --check  # 갱신 필요하면 exit 1
python3 engine/scripts/build_index.py --force  # 설명이 줄어드는 갱신도 강행
```

**구조는 기계가, 설명은 LLM 이.** 스크립트는 파일 목록·계층만 만들고, 각 줄의 설명은
**기존 index 에 있던 것을 그대로 보존**합니다. 새 파일은 `_(설명 없음)_` 으로 표시돼
`/gardener` 가 채울 자리를 남깁니다 — 스크립트가 사람이 쓴 설명을 덮어쓰는 일은 없습니다.

⚠️ 설명 회수는 `- [제목](경로) — 설명` **한 줄 = 한 파일** 형태만 잡습니다. 한 줄에 여러 파일을
묶은 큐레이션은 회수되지 않아 사라집니다. 그래서 **설명이 실제로 줄어드는 갱신은 거부합니다**
(exit 2, 사라질 항목 이름을 함께 출력). 아직 설명이 없던 항목과 새 파일은 손실로 세지 않습니다.

마커(`<!-- JW-MARKER:catalog -->`) 사이는 손편집 금지. 밖은 자유입니다.

### `assets_upload.py` — 무거운 원본을 MinIO 로

```bash
set -a; . ./.env; set +a
# 기본은 dry-run — 계획만 보여 주고 아무것도 쓰지 않습니다
python3 engine/scripts/assets_upload.py --namespace 홈서버 --slug first-setup \
  --src ~/받은자료 --source "어디서 받은 자료인지 한 줄"
# 맞으면
… --apply
```

키 규약 = `{namespace}/{YYYY-MM}/{slug}/`. `--month` 는 자료를 **받은** 달이지 내용의 연도가 아닙니다.

**무엇을 보장하나** (전부 실제 사고에서 나온 것들입니다):

| 보장 | 무엇을 막나 |
|---|---|
| 신원 = **sha256** (ETag·크기로 안 가름) | multipart ETag 는 md5 가 아니라, 크기만 같으면 같은 파일로 봐 버리는 것 |
| **멱등** — 같은 내용이면 skip | 중복 적재 |
| **왕복 이름 확인** — 올린 뒤 list·head 로 되읽음 | 한글 NFD↔NFC·공백·괄호 키가 조회에서 404 나는 것 |
| **전수 재해시** — 되받아 다시 잼 | **"올렸다"와 "올라갔다"는 다릅니다** |
| **음성 대조** — 없는 키가 404 인지 매번 확인 | "전부 있음"이 사실은 도구 고장인 경우 |
| **자동 삭제 금지** — stale 은 보고만 | 유일본 소실 |
| **정규화 충돌 중단** | 한쪽이 조용히 덮여 사라진 채 초록이 나오는 것 |

🔴 **`--no-verify` 로 검증을 끄고 초록을 보고하는 것은 검증이 아닙니다.**
prefix 루트에 `_manifest.json`(기계) + `_manifest.csv`(사람)가 함께 쓰입니다.
