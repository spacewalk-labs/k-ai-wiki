# wiki-upload — 자료를 `raw/` 에 투입

대상은 **이 레포**다. vault 루트 = `wiki-vault/`, 이 문서의 경로는 전부 그 기준이다
(`raw/ingest/…` = `wiki-vault/raw/ingest/…`). 규칙 정본 = 레포 루트 `AGENTS.md`.

## ⭐ 1단계 — 3문 인터뷰 (이 스킬의 핵심)

파일을 만들기 **전에** 주인에게 묻는다. 자료마다 한 번.

1. **왜 이걸 캡처했나?**
2. **여기에 대한 내 관점은 무엇인가?** (동의하나·반대하나·어디가 새로웠나)
3. **나중에 이걸 어떻게 써먹고 싶은가?**

- 답은 본문 맨 위 `## 왜 남기나` 절에 **주인의 말 그대로** 저장한다. 요약·윤색하지 않는다.
- **답이 안 나오면 그 자료는 넣지 않는다.** *"나중에 볼지도 몰라서"* 는 넣을 이유가 아니다 —
  그렇게 쌓인 것이 지식의 무덤이 된다.
- 여러 자료면 자료별로 짧게 묻되, 묶어서 한 번에 물어도 된다.

### ⚠️ "묻지 말고 추론하라" 와의 관계 (충돌 아님)

- **메타(제목·날짜·출처·태그) = 묻지 않는다.** 오늘 날짜·방금 맥락에서 다 추론된다.
  먼저 채우고 **추론값을 보고**해 틀린 것만 고치게 한다.
- **의도·관점(3문) = 반드시 묻는다.** 주인 머릿속에만 있어 추론이 불가능하고,
  추론하면 **주인의 생각을 지어내는 것**이 된다.

즉 **사실은 추론, 생각은 질문.**

## 2단계 — 투입

- 경로: `raw/ingest/<오늘>-<slug>.md` (slug = 제목 kebab)
- frontmatter:

```yaml
---
title:
source:        # 대화:<주제> | 파일경로 | URL
dated:         # 내용 속 날짜 > 파일 mtime > 게시일 > 오늘
collected_at:  # 오늘
tags: []
---
```

- 본문 = `## 왜 남기나`(3문 답변) → 다듬은 내용 → 출처.
- **동결 원칙**: 들어간 뒤 수정 금지. 갱신은 파일 수정이 아니라 **새 스냅샷 추가**.
  투입 시점의 가벼운 정리(깨진 인코딩·지저분한 붙여넣기)는 OK — 단 사실을 바꾸거나
  정보량을 줄이지 않는다.

## ⭐ 3단계 — 무거운 원본은 MinIO 로

PDF·xlsx·zip·고해상 이미지는 `.gitignore` 로 레포에서 빠진다.
**버리라는 뜻이 아니라 다른 데 두라는 뜻이다.** 로컬 경로 포인터만 남기는 것도 금지 —
`/tmp` 도 다운로드 폴더도 곧 사라진다.

```
무거운 원본  →  MinIO 버킷          (용량·versioning·링크썩음 방어)
작은 스크린샷 →  raw/assets/ (git)   (옵시디언에서 바로 보여야 한다)
md 정제본    →  raw/ingest/ (git)   (검색·[[링크]]·LLM 이 읽는 층)
```

**절차 3줄:**

1. **올린다.**

   ```bash
   set -a; . ./.env; set +a
   # 먼저 계획만 본다 (기본 dry-run — 아무것도 쓰지 않는다)
   python3 engine/scripts/assets_upload.py --namespace <주제영역> --slug <자료묶음> \
     --src <폴더> --source "<어디서 받은 자료인지 한 줄>"
   # 계획이 맞으면
   … --apply
   ```

   - `--namespace` = 자료가 속한 **주제 영역**(`홈서버`·`학습`·`재무`). 새로 만들기 전에
     버킷의 기존 값을 먼저 본다 — 매번 새 이름을 지으면 나중에 아무것도 못 찾는다.
   - `--slug` = 폴더명이 아니라 **무슨 자료인지**로 짓는다.
   - 도구가 알아서 하는 것: 멱등 skip · 올린 뒤 이름 왕복 확인 · 전수 재해시 · 음성 대조 ·
     `_manifest.json` 갱신. 🔴 **`--no-verify` 로 끄고 초록을 보고하지 않는다.**

2. **내용을 md 로 만든다.** 포맷마다 도구가 다르다.

   | 포맷 | 도구 | 주의 |
   |---|---|---|
   | PDF (텍스트) | `pdftotext -layout` | 폰트 인코딩이 깨지면 글자가 뭉개진다 — 그때가 OCR 자리 |
   | docx | `python-docx` | XML 이라 **표가 표로 남는다**. PDF 로 바꿔 OCR 하면 오히려 뭉개진다 |
   | pptx·hwpx | zip + XML 직접 | 표준 라이브러리로 충분 |
   | xlsx | `openpyxl` | 셀 값 그대로. 서식은 안 남는다 |
   | 스캔 PDF·이미지 | OCR | 없으면 **"OCR 안 함"을 정직히 적고** 원본 키만 남긴다 |

   ⚠️ **정제본은 원본이 아니다.** 표는 값이 살아도 행 정렬이 뭉개지고, 다단 조판은 읽기 순서가
   섞인다. frontmatter 에 `method:` 로 어느 경로로 뽑았는지 밝히고, 숫자·조항을 인용할 땐
   `sources` 의 `s3://` 키로 원본을 연다.

3. **대장에 적는다.** md 의 `sources` 에 `s3://<버킷>/<키>` 를 적는다.
   vault 안에서만 보고도 원본이 어디 있는지 알 수 있어야 한다.
   ⚠️ 같은 파일이 여러 곳에 붙어 있으면 **sha256 당 md 한 장**만 만들고,
   나머지 키는 그 md 에 함께 적는다.

## 4단계 — 반영

1. `log.md` 맨 아래에 한 줄 append: `## [YYYY-MM-DD] ingest | <제목>`
2. `python3 engine/scripts/build_index.py` (색인은 생성물 — 손으로 고치지 않는다)
3. `python3 engine/scripts/wiki_lint.py` 로 깨진 데가 없는지 본다
4. 내가 만든 경로만 **명시해서** `git add` → commit

> 🔴 `git add -A` 금지 — 실수로 `.env` 나 남의 변경까지 딸려 간다.

## 끝나면

- 투입 경로 + 추론한 메타(title·dated·source·tags) 한 줄 보고 → 틀린 것만 정정받는다.
- 후속이 필요하면 **"/gardener 로 wiki/ 초안 만들까요?" 제안만** (자동 실행 X).
